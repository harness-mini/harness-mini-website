# Ship: OG image + deploy

Two follow-on slices for the live site (existing project — recon already in
`ARCHITECTURE.md`, no founder funnel). Routed by `stage-viewer` as moderately
complex (two slices, one external/outward-facing action) → light PRD + issues.

## Five-Step pass (five-step)
1. **Less dumb** — "deploy + social preview" (owner: Matt). Question: do we need
   per-page dynamic OG images? No — one strong site-wide card is enough now.
2. **Delete** — Cut: per-route OG images, custom font loading in the OG (use the
   default), a custom domain, analytics. *Predicted add-back ≥10%:* a custom
   domain later.
3. **Simplify** — OG via the `next/og` file convention (static, 0 new deps);
   deploy from `site/` directly (no root `vercel.json` — Vercel auto-detects).
4. **Accelerate** — reuse the existing palette/strings; one image module, with
   `twitter-image` re-exporting it.
5. **Automate** — none beyond Vercel's own build; no CI added yet.

## Problem
The site has no social-share preview, and it isn't reachable on the web. Ship a
terminal-styled OG/Twitter card and deploy the production build to a public URL.

- [x] `og-image`: `/opengraph-image` is generated at build as a 1200×630 PNG in
      the terminal aesthetic; `<head>` of `/` includes `og:image` +
      `og:image:width/height` and `twitter:image`. Build stays green; routes
      remain static. *Verified: 200 image/png, 75.8 KB, PNG IHDR 1200×630; all
      `og:image*`/`twitter:image*` meta present; 10/10 routes static.*
- [x] `og-image`: alt text is set (`og:image:alt`). *Verified present on `/`.*
- [ ] `deploy`: `cd site && npm run build` succeeds and Vercel detects the app
      as Next.js (verified via `vercel build` or a dry run).
- [ ] `deploy`: the site is reachable at a public URL (depends on the user's
      Vercel auth — see Decisions), and that URL is wired into the footer +
      `metadataBase`.

- Custom font loading in the OG image (default font).
- Custom domain, web analytics, CI/CD pipeline.

## Decisions
- OG generated via the `next/og` file convention — static, no new runtime deps.
- Deploy target Vercel, run from `site/` (app is a subdir; no root config).
- **Vercel auth is the user's credential.** The CLI is installed but not logged
  in; method (CLI login / token / GitHub-import) to be chosen by the user, then
  recorded here. `gh` is authenticated (AtlanticF) if the GitHub-import path is
  chosen.
